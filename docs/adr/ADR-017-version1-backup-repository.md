ADR-017

Version1 バックアップリポジトリ作成と開発ブランチ運用

Status
Accepted

Date
2026-03-16

背景

ADR-011B により会話履歴取得機能が実装され、
AI会話は文脈追従が可能になった。

しかしこの段階は

会話継続品質の確認段階

履歴参照ロジックの改良余地あり

今後 ADR-012 以降の構造変更予定

という状況である。

このまま改修を進めると

会話品質が悪化した場合の復旧

新旧挙動比較

実験的変更

が困難になる。

特に AI会話品質は
コード差分ではなく挙動差分で評価する必要 がある。

そのため

現在の安定状態を Version1 として固定し、
今後の開発と分離する必要がある。

決定

次の二段階の方法で Version1 を固定する。

1. Version1 バックアップリポジトリ作成

現在のリポジトリを複製し、
バックアップ専用リポジトリとして保存する。

例

voice-ai-dashboard
voice-ai-dashboard-v1-backup

バックアップリポジトリは

原則更新しない

安定版保存

比較テスト

緊急復旧

の用途として使用する。

2. 本流リポジトリでブランチ運用

本流リポジトリでは branch を用いて開発を継続する。

例

main
release/v1-adr011b
feature/adr012
feature/adr016

release/v1-adr011b は
ADR011B 完了時点の安定版とする。

運用ルール
バックアップリポジトリ

原則

コード変更を行わない

Version1 の固定保存

用途

新旧挙動比較

バグ検証

緊急復旧

本流リポジトリ

開発はすべて branch 上で行う。

基本フロー

main
 ↓
feature branch
 ↓
テスト
 ↓
main merge

ADRごとに branch を作成する。

利点

この方式により次が可能になる。

1 安全な開発

本流改修が失敗しても
Version1へ即時復旧可能。

2 会話品質比較

同一入力に対して

backup版

改修版

の AI応答を比較できる。

3 開発速度向上

「戻れる地点」が固定されるため
改修判断が容易になる。

影響

コード構造への影響はない。

GitHubリポジトリ構造と
開発運用ルールのみ変更される。

を行う場合も
この Version1 バックアップは比較基準として使用できる。

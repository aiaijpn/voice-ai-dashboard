# V3.2 設計確定ドキュメント

## 未回答質問ストック × 協賛企業Wikipedia連携

---

# ■ 概要

V3.2では、AI会話の中で発生する
**協賛企業に関する未整備質問を自動収集し、ナレッジとして蓄積・育成する構造**を実装する。

従来の「テストで精度を上げる方式」から、

> **ユーザの実質問からデータを回収し、自然に精度が上がる構造**

へ移行する。

---

# ■ 目的

* 未回答質問を資産化する
* 協賛企業ナレッジ（Wikipedia）を育成する
* テスト工数を削減する
* 実際の需要データを収集する
* マネタイズにつながるデータ基盤を作る

---

# ■ コア思想

> **答えられなかった質問 = 価値のあるデータ**

---

# ■ システム構造

## 使用データストア（Google Sheets）

### 1. company_wiki（回答データ）

→ すでに回答できる企業情報

### 2. question_stock（未回答データ）

→ 回答できなかった質問の蓄積

---

# ■ 処理フロー

```
ユーザ発話
↓
V3.1 answerRules
↓
companyCandidates 抽出
↓
company_wiki 検索
↓
【ヒット】
→ wiki回答を返す

【非ヒット】
↓
AI応答（一般回答）
↓
question_stock 保存 / 更新
↓
未整備補足文を追加
```

---

# ■ 協賛企業質問の判定条件

以下のいずれかを満たす場合：

* companyCandidates が1件以上存在
* 協賛企業名がユーザ発話に含まれる

※ユーザへの確認（聞き返し）は行わない

---

# ■ company_wiki 設計

## 列構成

```
company_id
company_name
question_pattern
normalized_question
answer_text
status
created_at
updated_at
```

## 運用ルール

* `status = active` のみ検索対象
* `company_id` をキーに検索
* `normalized_question` で照合

---

# ■ question_stock 設計

## 列構成

```
company_id
company_name
user_question
normalized_question
asked_count
first_asked_at
last_asked_at
stock_status
wiki_answer
review_note
question_category
group_key
canonical_question
draft_answer
draft_answer_source
adopted_at
```

---

## ■ 同一質問の判定

キー：

```
company_id + normalized_question
```

---

## ■ 更新ルール

### 新規質問

* 新規行追加
* asked_count = 1

### 既存質問

* asked_count +1
* last_asked_at 更新

---

## ■ stock_status

```
new       未対応
answered  wiki反映済み
skip      採用しない
```

---

# ■ 未整備時の返答

```
その点は、まだ掲載情報が十分ではありません。改善のため記録しました。
```

※ユーザへの保存確認は行わない

---

# ■ 管理者運用フロー

① question_stock を確認
② 同種質問を整理
③ 回答文を作成
④ company_wiki に追加
⑤ stock_status を更新

---

# ■ 設計上の重要ポイント

## 1. company_id の完全一致

* 全データで統一必須

## 2. normalized_question の役割

* 完全一致キーとして使用

## 3. status と stock_status の分離

* status → 公開データ管理
* stock_status → 未処理データ管理

## 4. AIは補助、確定は人

* draft_answer は下書き用途
* 最終回答は管理者が確定

---

# ■ 本設計の本質

本機能は単なるFAQではない。

> **需要収集エンジン付きWikipedia**

---

# ■ マネタイズ視点

question_stock は以下の価値を持つ：

* 顧客の生の需要データ
* 企業ごとの改善ポイント
* 提案営業の根拠
* ナレッジ資産

---

# ■ 最終結論

V3.2は以下を実現する：

* 回答できるものは即回答
* 回答できないものは自動収集
* 収集データを元にナレッジを育成
* 使うほど賢くなる構造
